# dsh-TUI offline distribution

On Windows, open PowerShell and run `launcher/dsh-tui.ps1`. On Kylin V10 over SSH, allocate a PTY (`ssh -t host`) and run `launcher/dsh-tui.sh`. Use a writable program directory. No desktop session or administrator rights are required.

The first launch creates an isolated data root for this distribution. Defaults are `%LOCALAPPDATA%/dsh-tui-offline/<distributionId>` or `$XDG_DATA_HOME/dsh-tui-offline/<distributionId>` (falling back to `$HOME/.local/share/dsh-tui-offline/<distributionId>`), so superbpm and hxfl data stay separate by default. Set `DSH_TUI_OFFLINE_HOME` for this process to choose another absolute path. Moving the program directory does not move or delete user data.

Git, Git Bash on Windows, Python, Node, npm, and pip run from the bundle. npm and pip use the internal HTTPS indexes selected at build time and fail when those indexes are unavailable; they do not fall back to public package services. Install Java/JDK and Maven separately when a project needs them. The host environment supplies enterprise CA trust and network egress policy. The model API base URL is prefilled from the packaging profile into `config/offline.json`; edit it after installation and restart to apply. API keys are never bundled: users add them through the DSH provider flow, and credentials stay in this distribution's DSH credential store.

superbpm and hxfl use separate packaging profiles. Copy [`superbpm.example.json`](../../offline/profiles/superbpm.example.json) or [`hxfl.example.json`](../../offline/profiles/hxfl.example.json) to the matching local `.json` file in that directory, then fill the model API, update manifest, npm/Python URLs, toolchain directories, exact versions, and tested platform baselines. The actual profile files are Git-ignored; keep credentials out of them. Both package repositories are anonymously readable. The shared input contract is [`bundle-config.schema.json`](../../offline/bundle-config.schema.json). Lock each environment's extracted tool trees with [`toolchain-manifest.example.json`](../../offline/toolchain-manifest.example.json), [`toolchain-manifest.schema.json`](../../offline/toolchain-manifest.schema.json), and `node --import tsx/esm scripts/offline/lock-toolchain.mjs <platform> <tool-root> <metadata.json>`; the locked metadata records Node, Git, and Python license identifiers alongside versions and file hashes. Validate with `pnpm offline:validate:superbpm` or `pnpm offline:validate:hxfl`. Commit all source changes first. On each matching target OS and architecture, build one platform with `pnpm offline:build -- --profile <profile> --platform <platform> --out <empty-directory>` (`<profile>` is `superbpm` or `hxfl`). Build outputs and records are isolated per profile while the app SemVer stays the same. On a release workstation, merge the three outputs for one profile with `node --import tsx/esm scripts/offline/merge-manifests.mjs --profile <profile> --out <empty-directory> <win-dir> <kylin-x64-dir> <kylin-arm64-dir>` (`<profile>` is `superbpm` or `hxfl`). Upload each archive before replacing that environment's Nginx manifest. Keep untested platforms out of deployment manifests. The installed bundle includes an editable `config/offline.json`; distribute changed defaults by rebuilding the full bundle, not as a standalone config file.

The client checks the internal manifest in the background. Run `/update`, `./launcher/dsh-tui.ps1 update` on Windows, or `./launcher/dsh-tui.sh update` on Kylin to retry; the client displays the release notes and asks before downloading. Updates replace only the client release. SHA-256 detects changed or incomplete bytes, and the previous release stays available for startup rollback.

If the program directory is read-only, the updater stops before downloading and does not elevate privileges. It instructs the user to extract the matching full offline bundle into a writable directory and launch it there; reusing the same `DSH_TUI_OFFLINE_HOME` keeps existing settings and sessions.
