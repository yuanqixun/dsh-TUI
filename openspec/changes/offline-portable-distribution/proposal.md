# Proposal

## Why

内网无法访问互联网和软件包仓库，用户需要在 Windows 与 Linux 上解压即可启动 dsh-TUI，无须在线安装 Node.js、DSH 或依赖。内网已有兼容模型 API；本需求是客户端离线分发，不包含模型部署。

## What Changes

- 新增 Windows ZIP、Linux TAR.GZ 完整便携包，携带运行时、DSH、TUI、内置插件、预设、平台原生依赖与必要辅助程序。
- 使用当前源码构建产物和锁定的依赖闭包，在目标平台构建、验证；不从 npm 临时拉取同名最新版替代当前源码。
- 离线完成首次 profile 初始化，显式配置内网模型服务，避免启动、更新检查和插件发现隐式访问公网。
- 提供启动器、依赖清单、SHA-256 校验、第三方许可证、系统前置条件与中英文操作说明。
- 用干净目标环境验证无在线安装、原生依赖加载、模型工具调用和持久化恢复；仅为实测通过的系统/架构声明支持。

## Capabilities

### New Capabilities

- `offline-bundle`: 可追溯、平台明确、包含运行依赖的离线便携分发及完整性验证。
- `offline-runtime`: 首次离线启动、内网模型配置、无隐式公网依赖以及用户数据保留。

### Modified Capabilities

无；仓库此前没有 OpenSpec 基线。上述能力当前仅为变更提案，实施验收后再归档到主规格。

## Impact

预计涉及新增离线包构建脚本与平台流水线、既有 standalone 初始化逻辑、更新检查与插件目录网络入口、文档和聚焦回归。保留现有在线安装、npm 发布与便携版分发方式，不重写 DSH 域服务，不变更现有公共插件 API。

本次交付仅为提案文档，全部实施任务保持未完成。不生成二进制、不发布 Release、不向上游开 PR。

用户已确认 Windows 与 Linux、解压即用、已有内网兼容 API。系统版本、CPU 架构、Linux libc 和具体模型协议仍未提供：任务 1 为强制环境确认关口，未经确认不宣称兼容、不选定最终平台构建矩阵。
