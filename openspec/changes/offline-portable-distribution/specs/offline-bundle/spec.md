# Spec Delta

## Purpose

为无法访问互联网软件仓库的部署环境提供 Windows 和 Linux 完整客户端便携包，使部署人员能够识别平台兼容范围、验证包完整性，并在目标机器无需下载或编译依赖的条件下运行所声明的客户端功能。

## ADDED Requirements

### Requirement: 完整平台运行包

每个离线包 SHALL 携带对应目标平台的运行时、DSH、TUI、内置插件和预设、运行资源、必需原生模块与辅助程序；目标机无需 Node.js、npm、pnpm、编译器或开发者缓存。操作系统基本组件与任何无法随包分发的前置条件 MUST 显式列入兼容清单。

#### Scenario: 干净目标系统首次运行
- **WHEN** 在兼容清单中的干净系统解压包，未安装 Node/npm/pnpm，且公网不可达
- **THEN** 启动器可进入 TUI 或本地配置流程，且不尝试下载、安装或编译运行依赖

#### Scenario: 工具闭包可执行
- **WHEN** 执行包声明支持的文件读写、搜索、shell/子进程与图片处理流程
- **THEN** 所需平台模块和辅助程序可从包内或明确声明的系统组件获得，不临时下载依赖

### Requirement: 可验证的兼容范围

每个产物 SHALL 声明 OS、架构及最低系统库基线，并且 MUST 在匹配目标环境中验证后才能标记为支持。Windows 与 Linux SHALL 提供独立压缩包。

#### Scenario: 平台未确认
- **WHEN** 尚未确认 Linux 发行版、libc 或 CPU 架构，或缺少目标验收结果
- **THEN** 该目标标记为待确认或未验证，不宣称通用兼容

#### Scenario: 目标不匹配
- **WHEN** 用户选择与其机器不匹配的包
- **THEN** 包名与兼容说明可用于发现不匹配；运行时能够执行预检时，预检清楚报告不支持条件并终止启动

### Requirement: 可追溯且独立的内容

产物 SHALL 记录源码提交、运行时和主要组件精确版本、依赖清单、许可证及完整性摘要。运行内容 MUST 独立于构建机路径和缓存，不包含真实凭证或用户会话。

#### Scenario: 拷贝到另一台机器
- **WHEN** 将完整包拷贝到另一台兼容机器的含中文和空格目录
- **THEN** 启动与模块解析无需访问构建机路径，参数、工作目录和退出码正确传递

#### Scenario: 文件损坏
- **WHEN** 包内运行文件被修改或缺失后执行完整性检查
- **THEN** 检查报告失败和受影响路径，不将损坏包报告为完整
